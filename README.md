# Echo · AI Digital Twin Demo

Το Echo διαβάζει αρχεία TXT/PDF, κάνει OCR τοπικά για σαρωμένα PDF, αποθηκεύει chunks και embeddings στην SQLite και απαντά σε ερωτήσεις με σχετικά αποσπάσματα και αναφορές πηγών.

## Εκκίνηση χωρίς API key

Η εφαρμογή ξεκινά χωρίς `OPENAI_API_KEY`. Η επιλογή Cloud εμφανίζεται ως μη διαθέσιμη και δεν επιτρέπει upload ή ερωτήσεις μέχρι να ρυθμιστεί το key. Η επιλογή Ollama παραμένει διαθέσιμη όταν εκτελείται το Ollama και υπάρχουν τα μοντέλα.

Με Docker:

```bash
docker compose up --build
```

Άνοιξε http://127.0.0.1:8000. Αυτή η βασική εντολή δεν κατεβάζει ούτε εκκινεί μοντέλα Ollama.

## Cloud με OpenAI

Η backend υπηρεσία διαβάζει `OPENAI_API_KEY` από το τοπικό `.env`. Το key δεν φεύγει προς τον browser. Τα chunks αποστέλλονται στο OpenAI Embeddings API, ενώ στις ερωτήσεις αποστέλλονται μόνο τα επιλεγμένα chunks, η ερώτηση και οδηγίες στο OpenAI chat API. Η χρήση API μπορεί να επιφέρει χρέωση στον λογαριασμό που διαχειρίζεται το key. Το demo δεν εμφανίζει επίσημο υπόλοιπο ή δωρεάν quota.

Αν `.env` δεν υπάρχει, δημιούργησέ το από το παράδειγμα:

```bash
[ -f .env ] || cp .env.example .env
```

Άνοιξε το `.env` σε editor και συμπλήρωσε τοπικά:

Σε macOS μπορείς να το ανοίξεις με `open -e .env`.

```dotenv
OPENAI_API_KEY=το_key_της_ομάδας
OPENAI_EMBEDDING_MODEL=text-embedding-3-small
OPENAI_CHAT_MODEL=gpt-6-luna
```

Αποθήκευσε το αρχείο και επανεκκίνησε:

```bash
docker compose up --build
```

Για απευθείας εκτέλεση Python, σταμάτησε το Uvicorn με `Ctrl+C` και ξεκίνησέ το ξανά με `python -m uvicorn backend.main:app --reload`. Το backend διαβάζει το ίδιο project `.env`.

Τα `text-embedding-3-small` και `gpt-6-luna` είναι cloud υπηρεσίες, όχι μοντέλα που κατεβαίνουν τοπικά. Τα ονόματα αλλάζουν με τις μεταβλητές `OPENAI_EMBEDDING_MODEL` και `OPENAI_CHAT_MODEL`.

## Τοπικά με Ollama

Με Docker, ξεκίνησε το προαιρετικό profile:

```bash
docker compose --profile local up --build
```

Το profile χρησιμοποιεί το επίσημο `ollama/ollama` image και κατεβάζει αυτόματα τα μοντέλα την πρώτη φορά. Χρειάζεται internet, χρόνο και περίπου 1.2 GB για τα μοντέλα, συν επιπλέον χώρο για cache/runtime. Τα μοντέλα διατηρούνται στο Docker volume `ollama_data`. Μετά τη λήψη, τα embeddings και οι απαντήσεις δημιουργούνται τοπικά· η επεξεργασία μπορεί να είναι πιο αργή.

Προεπιλεγμένα μοντέλα:

- `qwen3-embedding:0.6b` για embeddings (περίπου 639 MB).
- `qwen3:0.6b` για απαντήσεις (περίπου 523 MB).

Τα ονόματα ρυθμίζονται με `OLLAMA_EMBEDDING_MODEL` και `OLLAMA_CHAT_MODEL`. Για απευθείας εκτέλεση σε Mac/Linux, εγκατέστησε το Ollama και κατέβασε τα μοντέλα με `ollama pull qwen3-embedding:0.6b` και `ollama pull qwen3:0.6b`. Το `OLLAMA_BASE_URL` είναι `http://localhost:11434` για απευθείας εκτέλεση· στο Compose ορίζεται αυτόματα για το Ollama container.

## Επιλογή λειτουργίας και αρχεία

Στην ενότητα «Προσθήκη», διάλεξε «Cloud με OpenAI» ή «Τοπικά με Ollama» και πάτησε το κουμπί αλλαγής. Πριν αλλάξει πάροχος, τα ήδη υπάρχοντα αρχεία επανεπεξεργάζονται με το αντίστοιχο embedding model. Τα προηγούμενα embeddings αντικαθίστανται μόνο όταν ολοκληρωθεί επιτυχώς η επεξεργασία. Η αναζήτηση χρησιμοποιεί το ίδιο provider/model με τα αποθηκευμένα chunks.

Η εξαγωγή κειμένου και το OCR σαρωμένων PDF εκτελούνται τοπικά με OCRmyPDF/Tesseract και γλώσσες ελληνικά/αγγλικά (`ell+eng`). Η βάση και τα αρχεία βρίσκονται στο `backend/data/` και διατηρούνται τοπικά.

Το πραγματικό `.env` εξαιρείται από Git και Docker build context. Μην προσθέτεις API keys σε κώδικα, logs ή συνομιλίες. Το `.env.example` δεν περιέχει πραγματικό key.

## Αρχική γνωριμία και προφίλ Echo

Η κινούμενη εισαγωγή και οι ερωτήσεις είναι προσωρινά εκτός της κανονικής εκκίνησης, ώστε η ανανέωση της σελίδας να ανοίγει απευθείας την εφαρμογή. Για να ξεκινήσεις τη γνωριμία χειροκίνητα, άνοιξε `http://127.0.0.1:8000/?onboarding=1`. Η διαδικασία περιλαμβάνει υποχρεωτικό πεδίο ονόματος, πέντε ερωτήσεις μονής επιλογής και προαιρετική προσθήκη CV. Οι απαντήσεις αποθηκεύονται στο προφίλ και ως δομημένο JSON persona στο `localStorage`.

Στην ενότητα «Προφίλ» μπορείς να δεις, να διορθώσεις, να εγκρίνεις, να απορρίψεις ή να διαγράψεις στοιχεία. Υπάρχουν επίσης απλές προτιμήσεις για σύντομες/αναλυτικές και φιλικές/επίσημες απαντήσεις. Αυτές δεν αποτελούν εκμάθηση προσωπικού τρόπου γραφής. Τα στοιχεία προφίλ, οι καταστάσεις τους, οι ημερομηνίες και η προέλευσή τους αποθηκεύονται στη SQLite βάση `backend/data/echo.sqlite3` στους πίνακες `twin_profile` και `profile_items`.

Το CV είναι προαιρετικό και μπορεί να δοθεί ως PDF/TXT ή ως επικολλημένο κείμενο. Το αρχείο διαβάζεται στη μνήμη, χρησιμοποιεί την υπάρχουσα εξαγωγή PDF/OCR (`ell+eng`) και δεν αποθηκεύεται ως αρχείο. Πριν σταλεί το περιεχόμενό του, το UI δηλώνει την ενεργή λειτουργία και ζητά επιβεβαίωση: με OpenAI αποστέλλεται το εξαγόμενο κείμενο στο cloud και μπορεί να υπάρξει χρέωση, ενώ με Ollama η εξαγωγή προτάσεων γίνεται τοπικά. Οι προτάσεις αποθηκεύονται μόνο ως «χρειάζεται έλεγχο», με όνομα αρχείου, σελίδα όπου υπάρχει και απόσπασμα που επαληθεύεται ότι βρίσκεται στο αρχείο. Ο χρήστης πρέπει να εγκρίνει ή να διορθώσει κάθε στοιχείο πριν χρησιμοποιηθεί. Δεν εξάγονται σκόπιμα ευαίσθητα χαρακτηριστικά.

Στην Καθοδήγηση, το Enter υποβάλλει την ερώτηση και το Shift+Enter εισάγει νέα γραμμή.

Στην καθοδήγηση, τα επιβεβαιωμένα/διορθωμένα στοιχεία προφίλ ορίζουν την ταυτότητα του Echo ως εκπροσώπου του χρήστη. Σχετικά αποσπάσματα αρχείων προσθέτουν πλαίσιο και συνοδεύονται από πηγές· πληροφορίες εγγράφων δεν παρουσιάζονται ως επιβεβαιωμένη προσωπική εμπειρία μέχρι να εγκριθούν στο προφίλ. Αν λείπει κρίσιμη πληροφορία, ο Echo ρωτά αντί να την επινοεί. Ο Γράφος δεν απαιτείται για τη δημιουργία του προφίλ.
